# SHORKFETCH 0.5.0

## Building
- SHORKFETCH is no longer statically compiled by default.
- Renamed the `EMBEDDED` build parameter to `NO_STR_CLEANING`.
- Added the `X86_ONLY` build parameter that excludes any code relating to CPU architectures other than x86 to reduce the binary size by ~10KB and speed up processing time
- `install.sh` now cleans up after itself if it fails/is aborted.

## Usage
- The `--bullets` parameter has been replaced with `--bullet` (for setting the bullet character only) and `--mode` (`b` for bullet, `n` for normal). This was done because future modes are being planned and tested, and it was prudent to use a single argument to change mode rather than multiple.
- Added the `--force-art` parameter that forces the SHORK ASCII art to display no matter the setting, number of fields or terminal size.

## Uptime
- Units have now been condensed. For example, "6 hours" becomes "6h" regardless of compact mode's status.

## Screen
- Displaying physical screen size has been disabled pending accuracy improvements.

## CPU
- Major internal CPU handling changes.
- ARM model names are better captured and more likely to reveal the host CPU beyond a generic ARM version number.
- Added recognition for HiSilicon, Faraday, Microsoft and Phytium ARM implementer IDs. 
- Added rudimentary m68k and MIPS handling support (at present, only interpreting their model name).
- Fixed a segmentation fault that occurs when handling CPU architectures SHORKFETCH does not explicitly target yet.
- Improved the logic that detects multi-CPU configurations.
- K7-based AMD Athlon and Duron model names are now given their microarchitecture name to help differentiate them without their exact model name. For example, "AMD Duron" (family 6, model 3, stepping 1) becomes "AMD Duron (Spitfire)".
- Corrected Sptifire-based AMD Duron model names that incorrectly call themselves "AMD Athlon".
- K7-based AMD Athlon XP and MP model names that lack the "XP" or "MP" component are generally corrected and given their microarchitecture name to help differentiate them without their exact model name. For example, "AMD Athlon" (6, 10, 0) becomes "AMD Athlon MP (Barton)".
- Fixed multi-CPU configuration detection for K7-based AMD Athlon MPs.
- Rearranged the position of "Mobile" in affected AMD Mobile Athlon, AMD Mobile Duron and AMD Mobile Sempron model names. For example, "Mobile AMD Sempron" becomes "AMD Mobile Sempron".
- Intel Pentium 4, Pentium D, Pentium Extreme and NetBurst-based Xeon model names are now generally given their microarchitecture name to help differentiate them without their exact model name. For example, "Intel Pentium D" (15, 6, 5) becomes "IBM Pentium D (Presler)".
- Completely replaced AMD Geode LX model names that are verbose yet don't reveal much. For example, "Geode Integrated Processor by AMD PCS" (433MHz) becomes "AMD Geode LX 700".
- Corrected Brisbane-based AMD Athlon 64 X2 model names that don't contain "X2".
- Corrected Allendale-based Intel Core 2 Duo E-series model names missing the "E". For example, "Intel Core 2 Duo 4400" becomes "Intel Core 2 Duo E4400".
- Corrected Westmere EX-based Intel Xeon model names that have a rogue space between the "E7-" prefix and the following four numbers. For example, "Intel Xeon E7- 4820" becomes "Intel Xeon E7-4820.

## GPU
- Improved how a possible integrated AMD Radeon GPU name is extracted from a CPU model name.
